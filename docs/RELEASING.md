# Releasing

1. Complete the Windows validation matrix and attach results to the release pull request.
2. Update `Version`, `AssemblyVersion`, and `FileVersion` in `Directory.Build.props`.
3. Run `scripts/build.ps1` on Windows.
4. Build the signed user-facing EXE with `scripts/package-installer.ps1` and the Store `.msixupload` with `scripts/package-msix.ps1`. The Store package may be submitted unsigned because Microsoft signs it after ingestion.
5. Confirm the EXE payload has no PDB files and that the app, hook host, hook DLL, installer, and uninstaller all validate against the release certificate.
6. Test install, startup, upgrade, repair, and uninstall in both `/CURRENTUSER` and `/ALLUSERS` modes on clean Windows 11 VMs.
7. Repeat the complete drag validation matrix from a per-user install, an all-users install, and the signed MSIX.
8. Generate SHA-256 checksums and an SBOM for every binary distribution artifact and the source archive.
9. Run Defender, SmartScreen, Windows App Certification Kit, and representative App Control/EDR policy checks.
10. Tag `vX.Y.Z` only after every signed artifact passes the release gates.

The package publisher string must exactly match the certificate subject. Never reuse or publish the local development certificate generated by `create-dev-certificate.ps1`.

The GitHub runtime ZIP is a diagnostic fallback, not the primary end-user installation path. Keep symbols in a separate archive and never include PDB files in the installer or MSIX.
